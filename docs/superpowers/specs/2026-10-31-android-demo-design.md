# 天天向上 Android 第一版实现设计

依据：[产品需求规格](../../spec-v1.md)。本设计描述如何把已确认的第一版范围做成可运行应用，不扩展产品功能。

## 目的与边界

服务个人跑步和训练场景。第一版的真实能力是能在后台持续运行的节拍器及其本地记录；课表、力量指导、AI 教练、报告、设备连接是清楚标记的交互演示。真正的语音播报、AI 通话、运动检测、设备同步和力量训练持久记录不在第一版内。应用不把演示数据说成真实效果。

## 考虑过的实现路线

- **Kotlin + Jetpack Compose（已选）**：单一 Android 平台，直接实现前台音频服务、通知和系统中断；界面状态用 Compose 表达。代价是将来跨平台需要单独实现。
- **Flutter**：界面复用能力较强，但节拍音频、后台运行和电话中断仍需要 Android 原生组件，首版多一层桥接。

## 组成与数据流

```text
Compose 页面 ──命令──> MetronomeService ──> 节拍音频 / 持续通知
      │                    │
      │<──运行状态──────────┘
      ├──> SessionRepository ──> 本地真实记录
      └──> DemoState ──────────> 内存中的演示课表、训练、报告、教练
```

- 单 Activity 承载 Compose 页面。顶层导航：首页、节拍器、课程、报告、我的；教练与设备从相关页面进入。首页突出“开始节拍”，并明确区分真实运行与演示入口。
- `MetronomeService` 是节拍播放和运行时长的唯一权威状态源。由用户在前台主动开始，以 `mediaPlayback` 类型前台服务持续运行，提供暂停／继续／结束通知操作。页面退出或锁屏不销毁会话。
- 播放线程用单调时钟安排拍点，并按当前 BPM 计算间隔；调速从下一拍生效。短 PCM 提示音在启动时预备，避免每拍创建播放器。页面定期读取服务状态显示时长，界面刷新不决定节拍时序。
- 系统电话占用音频时，服务继续累计运行时长，可暂时停止发声；音频可用后恢复节拍。若无法可靠判断状态，界面和通知显示声音状态，不把静音误报为正常播放。音频焦点策略以与音乐／有声内容共存为优先，并在真机上验证。真实节拍器只有提示音，不在开始、暂停、调速时语音播报。
- 真实记录使用本地存储：会话、开始／结束时间、累计运行时长、初始 BPM、调速事件、名称与结束原因。暂停期间不增加运行时长。服务定期保存可恢复的活动会话快照；进程被杀或重启后只做“意外结束”收尾，不自动播放。导出为用户选择位置的文件，删除只作用于真实记录。
- 演示状态单独存放，不调用真实记录仓库。演示流程可重置。所有演示页保持可见的“演示模式”标识；动作确认、课表修改、教练建议和示例报告仅改变演示状态。

## 关键流程

1. **跑步**：首页或节拍器页打开 → 设置 BPM、声音 → 手动开始 → 前台／后台／锁屏播放 → 可暂停、调速 → 手动结束 → 查看真实记录。
2. **电话**：节拍运行时电话接入 → 时长继续、声音按电话音频状态处理 → 结束后恢复声音。演示力量流程则在来电时冻结指导与进度，通话结束自动恢复。
3. **课程演示**：创建或复制课程模板 → 设置动作与每组参数 → 安排星期 → 启动当天课程 → 5 秒准备、起落、确认、休息依次推进 → 可暂停、跳过、提前结束 → 进入示例报告。演示按定义的虚拟时钟推进，以便交互测试，不写入真实记录。
4. **教练演示**：训练前进入咨询，或训练中呼叫 → 展示模拟对话与建议 → 用户确认才改变演示课程。力量训练在“通话”中暂停，结束后等待手动继续。
5. **报告与设备演示**：周／月／年示例视图注明数据来源；设备授权页面只展示未来接入流程，不请求真实设备权限。

## 界面方向

界面以运动中的一眼可读和单手操作为先。节拍器运行页以大号 BPM 数字和宽大的开始／暂停键为视觉中心；其余控制后退一层，避免跑步中误触。配色采用深蓝黑 `#102129`、浅灰白 `#F5F7F6`、清晰青绿 `#21B5A5`、暖黄 `#F2B84B`、警示红 `#C94B45`；青绿表示运行，暖黄表示准备或暂停，红色只用于结束与删除。使用系统中文无衬线字体，数字采用等宽数字特性。页面以左对齐信息块为主，较大的触控区和清楚的状态文案比装饰性图表更重要。演示标识固定在演示页面顶部，不使用与真实运行相同的成功提示。

## 错误和边界状态

- BPM 仅接受 160–220 的整数；越界或非数字时不启动、不改速，并给出范围提示。
- 通知权限被拒绝、音频设备断开、其他应用占用音频、服务异常时显示具体状态与可执行的恢复动作。
- 用户未确认的演示力量组不计为完成；示例报告不引用真实节拍器次数计算步数或体能。
- 只有一项真实训练能运行；从演示页进入节拍器时清楚退出演示训练。
- 应用重启时扫描未正常关闭的真实会话，标记意外结束并保留已确认时长；不得自动发声。

## 验证方式

- 单元测试覆盖 BPM 验证、调速事件、暂停时长累计、意外结束收尾和演示数据隔离。
- Android 测试覆盖服务启动、通知操作、记录保存与导出、演示流程和语义化状态。
- 真机检查覆盖锁屏、切换音乐／有声应用、来电及恢复、耳机断连、应用进程被杀与重启。需在至少两种 Android 版本和不同品牌设备上记录结果；无法在当前环境验证的项目须明确列为未验证，而非宣称通过。

## 尚由开发决定的细节

依构建环境选择兼容的 Gradle、Kotlin、Compose 版本；确定本地存储的具体实现与导出格式；选定短提示音音色。后续事件语音播报的触发阈值与文案属于后续版本。这些决定不得改变上述行为与[产品需求规格](../../spec-v1.md)的验收标准。
