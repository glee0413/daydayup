# 连续音频流节拍器实施计划

## 目标

将逐拍 `Handler` 唤醒与 `SoundPool.play()` 改为连续 PCM 音频流，让滴答声按采样帧排布。保留当前提示音、前台服务、音乐混播、步频和音量设置、会话记录。

## 方案

1. 为纯 Kotlin PCM 渲染器先写失败测试：180 BPM 在 48 kHz 下每 16000 帧一拍，非整数间距不累计漂移，变速与静音行为正确。
2. 加载现有 22.05 kHz、16 位单声道提示音并重采样到输出采样率。
3. 使用共享的 `AudioTrack` 流连续写入 PCM；尝试低延迟模式，按设备缓冲能力配置。音频写入线程提高优先级，记录欠载诊断。
4. 前台服务仅负责会话计时、电话状态和通知；不再逐拍触发声音。暂停、结束时停止音频流，继续时新建音频流。
5. 构建、单元测试，安装到连接的手机；检查启动、播放、暂停、变速、后台与日志。蓝牙耳机上的实际听感仍需用户验证。

## 风险与边界

蓝牙编码与耳机缓冲会增加绝对延迟。共享音频路径在不同手机上可能不授予低延迟模式；连续流仍可消除逐拍应用调度带来的声音间距波动。欠载和实际耳机声学输出分别需要软件日志与外部录音验证。
