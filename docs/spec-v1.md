# 天天向上：第一版产品需求规格

状态：需求已确认，第一版 demo 已实现

日期：2026-10-31

平台：Android
目标用户：产品发起人个人

## 1. 产品目标与版本边界

“天天向上”在运动过程中提供可听见、可控制的节奏和语音指导。第一版交付可运行的 Android 应用，其中**跑步节拍器是真实可用功能**；每周课表、力量训练指导、AI 语音教练、训练报告和设备连接交付**完整可点击的演示流程**。演示页面始终明确标注“演示模式”，示例数据与真实记录隔离，不暗示这些能力已经可用。

后续阶段逐步实现课表与力量指导、AI 通话、报告和设备接入。实现顺序不改变本规格中已确认的交互规则。

### 第一版验收范围

| 模块 | 第一版交付 | 后续真实能力 |
| --- | --- | --- |
| 跑步节拍器 | 可播放、调速、后台运行、记录与中断恢复 | 可结合真实运动数据 |
| 每周课表 | 可点击的创建、安排、调整演示 | 持久化课表与执行 |
| 力量指导 | 完整训练流程演示 | 定时语音指导与训练记录 |
| AI 教练 | 通话入口及对话流程演示 | 联网实时语音交互 |
| 训练报告 | 标为示例的周、月、年报告 | 基于实际记录计算 |
| 设备连接 | 授权和连接流程演示 | 按需接入手表等设备 |

第一版不把模拟训练、示例报告或占位通话写入真实训练记录；不把节拍次数推算为实际步数、距离或运动成绩；不提供姿势识别或实时动作纠错。

## 2. 主要页面与导航

1. **首页**：今日课程卡片、快速开启节拍器、最近真实节拍器记录、演示功能入口。真实与演示内容有清晰标识。
2. **节拍器设置与运行页**：步频数值、±5 调节、具体数值输入、开始／暂停／继续／结束、节拍音量、提示音开关、当前时长。
3. **节拍器记录页**：按日期查看持续时间、设定步频及调速过程，支持删除记录。
4. **课程模板与每周安排页（演示）**：创建或复制模板、添加动作、按星期安排、临时改期和补练。
5. **力量训练页（演示）**：准备、动作指导、组间及动作间休息、确认每组结果、暂停、跳过、提前结束。
6. **AI 教练页（演示）**：训练前咨询、训练中呼叫、建议确认、通话结束返回训练。
7. **报告页（演示）**：周、月、年视图，示例数据标识及数据来源说明。
8. **设置与数据页**：声音设置、真实记录导出与删除入口、数据与隐私说明、未来设备连接入口。

演示模式支持走通“编课表→训练→看报告→咨询教练”的流程。演示数据独立保存或重置，不混入真实节拍器记录。

## 3. 跑步节拍器：第一版真实功能

### 3.1 设置与操作

- 一声节拍提示对应一步。默认可选范围为 **160–220 步／分钟**；按钮每次增减 **5**，同时允许输入该范围内的具体整数值。越界输入应给出提示并阻止应用。
- 用户手动开始和结束；不要求设置目标时长。运行中可暂停、继续和调速。调速从下一拍起生效，不重启本次记录。
- 节拍音量独立可调，提示音可开关；节拍声与音乐或有声读物同时播放。第一版真实节拍器不做语音播报。
- 离开应用、锁屏或切换到音乐、微信读书等音频应用后，节拍计时和声音持续运行。运行时显示持续通知，含暂停／继续和结束操作；调速在应用内完成。
- 运行中显示步频、已运行时间、播放状态和当前声音设置。

### 3.2 来电与异常

- 电话期间**节拍计时继续**，不要求节拍声与电话声音同时可听；通话结束后自动恢复可听的节拍声。界面显示本次运行仍在继续。
- 应用被系统结束或手机重启后，不自动重新播放。再次打开时说明上次运行意外结束，并保留可确认的已运行时长。
- 用户手动暂停时停止声音并冻结本次运行时长；继续后沿用同一条记录。用户手动结束后保存记录。

### 3.3 真实记录

记录日期、开始与结束时间、实际运行时长、初始步频及每次调速的时间与新步频。记录名称可修改，整条记录可删除；开始／结束时间和步频变化保留为原始事实，不提供逐项改写。页面称为“节拍器使用记录”，不得称为实际步数、跑步距离或成绩。

## 4. 课表与力量训练：第一版演示，后续实现

### 4.1 课表结构

- 用户创建可复用的课程模板，再安排到每周指定日期。同一天安排一项主要训练；允许临时改期或补练。
- 提供常用动作供选择，并允许完全自定义动作。课程包含有序动作；动作包含组数，每组可分别设置目标次数、重量、起落节奏与组间休息；动作间休息可设置。模板可复制修改。
- 开始前可调整**本次训练**。开始后可暂停、跳过动作或组、提前结束。只有明确选择“保存到课表”才修改每周模板。
- 执行时以用户确认的本次课表为准；AI 建议不得直接覆盖它。

### 4.2 指导流程与默认值

每组依次进入 **5 秒准备 → 起落语音指导 → 结果确认 → 休息 → 下一组或动作**。默认一次动作“起”2 秒、“落”2 秒；组间休息 60 秒，动作间休息 90 秒，均可在课表中修改。倒计时最后 3 秒播报提醒。下一组开始前播报动作名称、目标次数及重量。

组末由用户确认“完成、少做、跳过”，可记录实际次数、重量和主观难度。未经确认不把预设次数当作完成次数。固定语音负责节奏、次数、休息和预先写好的动作要点；没有传感器或摄像头依据时，不声称识别动作姿势或实时纠错。

同一时间只运行一项训练。未来如课程需要节拍，把节拍配置为课程内的环节，不同时启动独立节拍器与课程计时器。

### 4.3 暂停与恢复

主动暂停时停止指导声并冻结动作或休息倒计时。来电时自动暂停力量指导的语音、计时和进度；通话结束后自动从暂停点恢复。AI 教练通话与此不同：发起 AI 通话时自动暂停力量指导，结束通话后由用户手动继续。

## 5. AI 语音教练：第一版演示，后续实现

- 提供训练前咨询及训练中的“呼叫教练”入口，支持语音提问、请求暂停和询问下一步。
- 教练可提出动作、重量或课表调整，但必须先展示变更内容，用户确认后才执行。不得无提示改写已确认的训练计划。
- 跑步节拍计时在教练通话期间继续；通话中节拍声音的处理遵循电话场景：不要求与通话同时可听，结束后恢复。力量指导在 AI 通话期间暂停，结束后手动继续。
- 真实 AI 通话需联网，并在开始前说明数据处理方式。网络不可用时给出明确提示；不默认保存通话录音。
- 对疼痛、伤病等问题，不给出确定诊断；提示停止当前动作并寻求专业评估。

后续语音播报按训练事件触发，例如达到用户设置的运动时长，或接入测量设备后检测到心率过高。节拍器本身只发节拍提示音，不播报开始、暂停或步频变化。第一版可在演示流程中展示这些事件提醒，但不实现真实语音播报，也不凭空生成心率告警。

## 6. 训练报告与设备：第一版演示，后续实现

- 报告按周一至周日、自然月、自然年汇总。训练按实际完成日期归档；计划完成率对照该周期内安排的课表。
- 报告分为计划与实际完成情况、训练量趋势（动作、组次、重量、时长）和主观感受（难度与恢复）。缺少数据时显示“数据不足”，不推断体能提升。
- 第一版仅使用显著标为“示例”的演示数据展示报告。真实节拍器使用记录可单独查看，不填充为未经证实的力量训练或跑步成效。
- 后续按需接入手表等测量设备，再增加心率等设备指标。设备连接需用户主动授权，并明确数据来源。

## 7. 数据、隐私与离线规则

- 真实训练记录默认保存在手机，提供导出和删除。演示数据与真实数据隔离，演示流程可重置。
- 节拍器及未来已保存课表的固定语音指导应能离线使用；AI 实时通话需要网络。
- 首次使用某项需要授权的设备能力时才请求相应权限。AI 通话开始前说明联网及数据处理；默认不保存录音。
- 报告中每项指标应能追溯为手动确认、节拍器运行记录或设备测量，避免混淆目标值、示例值和实际值。

## 8. 第一版验收标准

1. 用户能在 160–220 范围内按 5 调节或输入具体整数步频；启动后每步频单位产生相应节拍，运行中改速不中断本次记录。
2. 用户切换到其他应用或锁屏后，节拍计时及声音继续；可通过持续通知暂停、继续或结束。音乐或有声内容可与节拍声同时播放，节拍音量独立可调。
3. 来电时节拍计时不断；通话结束后节拍声自动恢复。通话中不以“节拍声必须可听”为验收条件。
4. 手动暂停冻结运行时长，继续沿用原记录；结束后产生一条含时间、时长及调速过程的真实记录。被系统结束或重启后不会自行重新播放。
5. 课表、力量指导、AI、报告及设备连接入口均可按设计流程点击演示，显著标注“演示模式”；其示例数据不会出现在真实记录中。
6. 演示力量流程包含 5 秒准备、起落节奏、最后 3 秒休息提醒、组末结果确认及电话／AI 通话两种不同的恢复路径。
7. 报告示例区分计划与实际，说明数据来源；无实际数据时不展示虚构的个人训练效果。
8. 真实记录可导出或删除；AI 通话演示说明未来联网及数据处理要求，不默认开启录音保存。

## 9. 开发前需验证的实现条件

这些是实现与验收时要检查的条件，不改变已确认的产品行为：目标 Android 版本的后台持续运行与音频控制、与常用音乐和有声内容应用同时播放的表现、电话音频切换及结束后的自动恢复、不同品牌设备的省电策略对运行的影响。若某设备无法达到要求，应用应明确显示状态，不把无声或中断误报为正常运行。
